# TaxDesk 검증설계서 (Verification Design)

> 버전 1.0 · 2026-07-06 · 구현설계서 v1.0 기준

## 1. 검증 전략 개요

| 레벨 | 도구 | 대상 | 실행 시점 |
|------|------|------|----------|
| L1 정적 검증 | TypeScript strict, ESLint | 전체 코드 | 커밋 전 / CI |
| L2 단위 테스트 | Vitest | 기한 계산, 자동화 규칙 평가, zod 스키마, 유틸 | 커밋 전 / CI |
| L3 통합 테스트 | Vitest + Supabase 로컬(or mock) | 서버 액션, cron 핸들러 멱등성 | CI |
| L4 RLS 검증 | SQL 테스트 시나리오 | 권한별 접근 매트릭스 | Supabase 마이그레이션 후 |
| L5 E2E | Playwright | 핵심 사용자 여정 5개 | 배포 전 |
| L6 수동 검증 | 체크리스트 | UI/UX, 반응형, 다크모드 | 릴리스 전 |

CI: GitHub Actions — `lint → typecheck → unit → build` (PR마다), E2E는 수동/야간.

## 2. L2 단위 테스트 명세 (핵심)

### 2.1 기한 계산 `lib/deadlines.ts` — 가장 중요한 로직

| ID | 케이스 | 기대 결과 |
|----|--------|----------|
| U-D-01 | 원천세 매월 10일, 평일 | 해당 월 10일 |
| U-D-02 | 기한일이 토요일 | 다음 월요일로 순연 |
| U-D-03 | 기한일이 일요일 | 다음 월요일로 순연 |
| U-D-04 | 기한일이 공휴일(holidays 테이블) | 다음 영업일로 순연 |
| U-D-05 | 순연된 날이 또 공휴일(연휴) | 연휴 종료 후 첫 영업일 |
| U-D-06 | 부가세 확정 1/25 연도별 생성 | 연 4회(1·4·7·10월) 정확 생성 |
| U-D-07 | 연간 규칙(법인세 3/31) | 연 1회 생성 |
| U-D-08 | rollover=false 규칙 | 주말이어도 순연 안 함 |
| U-D-09 | D-day 계산(오늘 기준 D-n) | 음수(경과)/0/양수 정확 |

## 3. L3 통합 테스트

| ID | 시나리오 | 검증 포인트 |
|----|----------|-------------|
| I-01 | cron 핸들러: CRON_SECRET 불일치 | 401 반환, 실행 안 됨 |
| I-02 | cron 핸들러: 같은 날 2회 호출 | 2회차 skipped, 태스크 중복 0 |
| I-03 | 시즌 일괄생성 액션 | 대상 필터 정확, 알림 n건 생성 |
| I-04 | KB 수정 | kb_revisions에 이전 버전 push |
| I-05 | 월 기장료 청구 생성 | (client, period) 중복 시 skip |
| I-06 | 입금 기록 → 완납 | invoice.status = paid 전환 |
| I-07 | 상담이력 → 지식화 승격 | KB 생성 + note.promoted_kb_id 연결 |

## 4. L4 RLS 접근 매트릭스 검증

각 셀을 SQL로 실행(`set request.jwt.claims`)해 허용/거부 확인:

| 액션 | staff | manager | admin | 타 org 사용자 |
|------|-------|---------|-------|---------------|
| clients SELECT | ✅ | ✅ | ✅ | ❌ |
| clients DELETE | ❌ | ✅ | ✅ | ❌ |
| invoices INSERT | ❌ | ✅ | ✅ | ❌ |
| automation_rules UPDATE | ❌ | ❌ | ✅ | ❌ |
| notifications SELECT(타인 것) | ❌ | ❌ | ❌ | ❌ |
| audit_logs SELECT | ❌ | ❌ | ✅ | ❌ |
| profiles.role 자가 상승 | ❌ | ❌ | — | ❌ |

파일: `tests/rls/rls_matrix.sql` — 시나리오별 `DO` 블록 + 예상 결과 주석.

## 5. L5 E2E 핵심 여정 (Playwright)

| ID | 여정 | 단계 요약 |
|----|------|----------|
| E-01 | 온보딩 | 가입 → 사무소 생성 → 대시보드 진입 |
| E-02 | 거래처 수임 | 거래처 등록 → 담당자 배정 → 상세에서 상담이력 추가 |
| E-03 | 시즌 업무 | 템플릿 선택 → 부가세 대상 일괄 생성 → 칸반에서 완료 처리 → 대시보드 진행률 반영 |
| E-04 | 지식저장소 | 문서 작성 → 검색으로 재발견 → 수정 → 개정 이력 확인 |
| E-05 | 미수금 | 월 청구 생성 → 입금 기록 → 미수금 잔액 0 확인 |

## 6. L6 수동 검증 체크리스트 (릴리스 게이트)

- [ ] 라이트/다크 모드 전 화면 대비 확인 (WCAG AA)
- [ ] 1280px / 768px 반응형 (사이드바 접힘)
- [ ] 한국어 날짜(YYYY.MM.DD)·통화(₩ 천단위) 표기 일관성
- [ ] 빈 상태(empty state) 화면 전부 안내 문구 존재
- [ ] D-day 배지 색상 규칙 (D-7 warn / D-3 danger / 경과 bold)
- [ ] 로그아웃 후 보호 라우트 접근 시 로그인 리다이렉트
- [ ] 서비스 롤 키가 클라이언트 번들에 미포함 (`grep` 검사)

## 7. 성능·보안 기준

| 항목 | 기준 |
|------|------|
| 대시보드 서버 응답 | < 1.5s (거래처 500건 기준) |
| KB 검색 | < 500ms (문서 1,000건) |
| 목록 페이지네이션 | 기본 50건, 서버 사이드 |
| 인증 | 모든 (app) 라우트 middleware 가드 |
| 입력 검증 | 서버 액션 100% zod 통과 후 처리 |
| 비밀키 | SERVICE_ROLE·CRON_SECRET 서버 전용, env 문서화 |
| 감사 | 쓰기 액션 audit_logs 기록률 100% (핵심 도메인) |

## 8. 인수 기준 (Definition of Done)

1. `npm run lint && npm run typecheck && npm run test && npm run build` 전부 통과
2. 마이그레이션 SQL이 빈 Supabase 프로젝트에 순서대로 적용 가능
3. 시드 데이터로 E2E 여정 E-01~E-05 수동 재현 가능
4. README에 Supabase/Vercel 배포 절차 문서화
