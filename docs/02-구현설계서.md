# TaxDesk 구현설계서 (Implementation Design)

> 버전 1.0 · 2026-07-06 · 기획서 v1.0 기준

---

## 1. 시스템 아키텍처

```
┌──────────────────────────── Vercel ────────────────────────────┐
│  Next.js 15 (App Router, TypeScript)                           │
│  ├─ Server Components: 목록/상세 조회 (Supabase 서버 클라이언트) │
│  ├─ Server Actions: 생성/수정/삭제 (검증: zod)                  │
│  ├─ Route Handler: /api/cron/automation  ← Vercel Cron (매일)  │
│  └─ middleware.ts: 세션 갱신 + 인증 가드                        │
└───────────────┬────────────────────────────────────────────────┘
                │ @supabase/ssr (cookie 기반 세션)
┌───────────────▼──────────── Supabase ──────────────────────────┐
│  Auth (email/password, 초대 플로우)                             │
│  Postgres: 스키마 + RLS + FTS(tsvector/trigram) + 트리거        │
│  Storage: documents 버킷 (RLS)                                 │
└────────────────────────────────────────────────────────────────┘
```

**핵심 결정**
- D1. 데이터 접근은 전부 Supabase RLS 통과. 서비스 롤 키는 cron 핸들러에서만 사용(CRON_SECRET 검증 후).
- D2. 자동화 스케줄러는 Supabase Edge Function 대신 **Vercel Cron → /api/cron/automation** 채택.
  이유: 배포 파이프라인 단일화, 로컬 테스트 용이. 멱등성은 `automation_runs` 테이블로 보장.
- D3. 신고기한은 하드코딩이 아닌 **tax_deadline_rules 테이블 + 순연 로직(공휴일 테이블)**로 계산.
- D4. single-tenant로 시작하되 모든 테이블에 `org_id` 포함 → 멀티테넌트 확장 시 RLS 조건만 강화.

## 3. 데이터 모델 (ERD)

```
orgs ─┬─ profiles(직원, auth.users 1:1, role: admin|manager|staff)
      ├─ clients(거래처) ─┬─ client_notes(상담이력)
      │                   ├─ documents(파일 메타)
      │                   ├─ invoices(청구) ── payments(입금)
      │                   └─ tasks ── task_items(체크리스트)
      ├─ task_templates ── task_template_items
      ├─ tax_deadline_rules(신고기한 규칙)
      ├─ holidays(공휴일)
      ├─ automation_rules ── automation_runs(실행이력)
      ├─ events(사내 일정)
      ├─ kb_documents ── kb_revisions
      ├─ notifications
      └─ audit_logs
```

### 3.1 주요 테이블 정의

```sql
-- 직원
profiles(id uuid PK = auth.users.id, org_id, name, role text check in
  ('admin','manager','staff'), phone, is_active bool, created_at)

-- 거래처
clients(id uuid PK, org_id, business_no text unique(org),  -- 000-00-00000
  name, ceo_name, client_type text check in ('corp','general','simplified','exempt'),
  industry, contact_name, contact_phone, contact_email,
  assignee_id → profiles, monthly_fee int, adjustment_fee int,
  engaged_on date, disengaged_on date, disengage_reason text,
  status text check in ('active','terminated') default 'active',
  homtax_agreed bool default false,  -- 홈택스 수임동의 여부(수기)
  withholding bool default true,     -- 원천세 대상
  vat_applicable bool default true,  -- 부가세 대상
  notes text, created_at, updated_at)

-- 상담/연락 이력
client_notes(id, org_id, client_id, author_id, channel text check in
  ('call','visit','kakao','email','etc'), content text,
  promoted_kb_id uuid null → kb_documents, created_at)

-- 신고기한 규칙 (시드 제공, 관리자 편집 가능)
tax_deadline_rules(id, org_id null(전역), code text, -- 'WHT_MONTHLY','VAT_1Q'...
  name, description, month int null, day int, frequency text check in
  ('monthly','quarterly','half','yearly'), applies_to text check in
  ('all','corp','individual','vat','withholding'),
  rollover bool default true, active bool)

holidays(date PK, name)  -- 대체공휴일 포함 시드

-- 업무
tasks(id, org_id, title, description, client_id null, assignee_id,
  due_date date, priority text check in ('low','normal','high','urgent'),
  status text check in ('todo','doing','review','done') default 'todo',
  source text check in ('manual','automation','bulk'),
  template_id null, rule_code text null, period_key text null, -- 'VAT_1Q:2026' 멱등키
  completed_at, created_by, created_at, updated_at)
task_items(id, task_id, content, done bool, sort int)

-- 업무 템플릿
task_templates(id, org_id, name, description, default_priority, created_by)
task_template_items(id, template_id, content, sort)

-- 자동화
automation_rules(id, org_id, name, trigger_type text check in
  ('deadline','monthly_day','status'), trigger_config jsonb,
  -- 예: {"rule_code":"VAT_1Q","days_before":24} / {"day":1}
  action_type text check in ('create_tasks','notify'),
  action_config jsonb, active bool, created_at)
automation_runs(id, rule_id, run_key text, -- rule_id+period 멱등
  ran_at, result jsonb, unique(rule_id, run_key))

-- 일정
events(id, org_id, title, starts_at, ends_at, all_day bool,
  kind text check in ('internal','deadline','leave','training'),
  owner_id, client_id null, created_at)

-- 지식저장소
kb_documents(id, org_id, title, content text(md), category text check in
  ('tax_law','manual','case','policy','scrap'),
  tags text[], source_url text null, author_id, is_archived bool,
  search tsvector generated,  -- title+content, 'simple' config + pg_trgm 인덱스
  created_at, updated_at)
kb_revisions(id, doc_id, title, content, editor_id, created_at)

-- 청구/미수금
invoices(id, org_id, client_id, kind text check in ('monthly','adjustment','etc'),
  period text, -- '2026-07'
  amount int, issued_on date, due_on date,
  status text check in ('draft','issued','paid','overdue') default 'issued',
  unique(org_id, client_id, kind, period))
payments(id, invoice_id, amount, paid_on, method, memo)

-- 문서함
documents(id, org_id, client_id null, doc_type text check in
  ('contract','poa','id_copy','etc'), title, storage_path text,
  expires_on date null, uploaded_by, created_at)

-- 알림 (단일 채널)
notifications(id, org_id, user_id, type text check in
  ('deadline','task_assigned','task_overdue','mention','billing','system'),
  title, body, link text, read_at timestamptz null, created_at)

audit_logs(id, org_id, actor_id, action, entity, entity_id, diff jsonb, created_at)
```

### 3.2 RLS 정책 요약

| 테이블 | SELECT | INSERT/UPDATE | DELETE |
|--------|--------|---------------|--------|
| profiles | 같은 org | 본인(제한 컬럼) / admin | admin |
| clients, tasks, events, kb_*, documents | 같은 org 전체 | 같은 org (담당 여부 무관 — 소규모 사무소는 상호 열람이 기본) | manager+ |
| invoices, payments | 같은 org | manager+ | admin |
| automation_rules, tax_deadline_rules | 같은 org | admin | admin |
| notifications | user_id = auth.uid() | 시스템(service role) + 본인 read_at | 본인 |
| audit_logs | admin | 시스템 | 불가 |

헬퍼: `current_org_id()`, `current_role()` — profiles 조회 `security definer` 함수.

### 3.3 기한 계산 로직 (`lib/deadlines.ts`)

```
computeDeadline(rule, year) → date
  1. rule.frequency에 따라 기준일 산출 (monthly: 매월 rule.day 등)
  2. rollover=true면 토/일/holidays에 해당 시 다음 영업일로 순연
generateYearDeadlines(rules, year) → 캘린더 표시용 배열
```

시드 규칙(발췌): 원천세 매월 10일 / 부가세 1·4·7·10월 25일 / 법인세 3/31 /
종소세 5/31 / 성실신고 6/30 / 사업장현황 2/10 / 지급명세서(근로) 3/10 /
원천세 반기납 1/10·7/10 / 면세사업장현황 2/10 / 법인세 중간예납 8/31.

## 4. 자동화 엔진 설계 (M5)

```
Vercel Cron (daily 00:10 KST) → POST /api/cron/automation (CRON_SECRET 헤더 검증)
  1. active 규칙 로드
  2. 트리거 평가:
     - deadline: computeDeadline(rule_code, 올해) - days_before == 오늘 ?
     - monthly_day: 오늘 일자 == config.day ?
  3. run_key = `${rule_id}:${periodKey(오늘)}` 로 automation_runs 존재 확인 → 있으면 skip (멱등)
  4. 액션 실행:
     - create_tasks: 대상 거래처 필터(vat_applicable 등) → tasks bulk insert
       (period_key 유니크 인덱스로 이중 방어) + 담당자 notifications insert
     - notify: 조건 대상에게 notifications insert
  5. automation_runs 기록 { created: n, skipped: n }
추가: 지연 태스크 스캔(due_date < today & status != done) → task_overdue 알림(1일 1회)
```

## 5. 주요 화면 설계 (11개 라우트)

## 6. 서버 액션 (도메인별 대표)

- `clients`: create/update/terminate(사유 필수)/reassign(일괄)
- `tasks`: create/updateStatus/bulkCreateFromTemplate(대상 필터 → n건 생성)
- `kb`: create/update(→ kb_revisions 자동 push)/archive, `promoteNoteToKb`
- `billing`: generateMonthlyInvoices(중복 방지)/recordPayment(완납 시 status=paid)
- `notifications`: markRead/markAllRead
- 전 액션: zod 검증 → 권한 확인(RLS + 앱단 이중) → audit_logs 기록
